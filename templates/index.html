OOP & SOLID Architecture Reference

The 4 Pillars of OOP

Encapsulation

Bundling state with methods while restricting direct external access to preserve invariants.

Abstraction

Hiding implementation details and presenting only essential, high-level interfaces.

Inheritance

Deriving new classes from existing ones to share behavior and establish 'IS-A' taxonomies.

Polymorphism

Providing a uniform interface for different underlying types (compile-time overloading, runtime vtables).

SOLID Principles

S — Single Responsibility

A module or class should have only one reason to change, serving a single stakeholder.

O — Open/Closed

Software entities should be open for extension but closed for modification.

L — Liskov Substitution

Subtypes must be substitutable for supertypes without breaking program invariants.

I — Interface Segregation

Clients shouldn't be forced to depend on methods they do not consume.

D — Dependency Inversion

High-level policy should depend on abstractions, not on concrete low-level details.

GoF Design Patterns

Creational: Factory Method, Abstract Factory, Builder, Singleton.
Structural: Adapter, Decorator, Facade, Composite, Proxy.
Behavioral: Strategy, Observer, Command, State, Template Method.
